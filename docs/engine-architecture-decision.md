# Engine Architecture Decision
Decision: Option A+D — optimized Swift with better macOS APIs. Evidence: baseline showed the periodic cost was /bin/ps process spawning (100 ms), not Swift computation; filesystem traversal measured 12 ms per 2,000 files. proc_listpids removed the spawn entirely (sample x5: 521 -> 3-13 ms). Bounded GCD parallelism addresses the only remaining sequential cost. Go would add IPC/process overhead to save <10 ms per 2,000 files; C would add unsafe memory management for syscalls Swift already makes. Neither is justified by measurements. Revisit only if profiling on real 500k-file trees shows dirSize dominating after parallelism.
